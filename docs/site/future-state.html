05

Risks

Known ways this plan can go wrong. None of them are hypothetical.

Risk 01

Thread affinity

The off-thread GameAction.invoke path is the number-one nondeterminism risk. Scenario injection must run on the game thread while parked.

Risk 02

Engine / AI interference

Mana payment, confirms, trigger ordering, and other non-overridden callbacks can drift a scripted line away from the intended one.

Risk 03

Loop-detection fidelity

Signatures may not recur bit-identically. This needs a deliberate signature definition and a bounded iteration budget.

Risk 04

Scenario / state-hash collisions

Library order, card ids, summoning sickness and attachments are excluded from state_hash today, so distinct scenarios can collide.

Risk 05

One game per process

A single active game per harness process constrains parallel witness search. Snapshots also cap at 32 live tokens.

Risk 06

Card resolution ambiguity

Names must resolve to exactly one PaperCard; double-faced, split, specialize and token faces need explicit handling.

Risk 07

No structured Spellbook steps

Only prose descriptions are imported. Combo lines must be driven from ontology links unless the steps are re-imported.

06

The bar

The bar for calling anything "novel" is deliberately high — engine-verified and independently sourced, or it stays a candidate.
